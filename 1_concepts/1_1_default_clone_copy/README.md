## Default values

В [Rust] существует стандартный способ работы со значениями по умолчанию для типов с помощью трейта [`Default`]. Ознакомьтесь с [its official docs][`Default`], чтобы понять принцип работы.

Его можно автоматически вывести, но только для `struct`, все члены которой имеют реализацию ['Default']. Он реализован для множества типов в стандартной библиотеке, а также используется в удивительно большом количестве мест. Поэтому, если ваш тип имеет значение, которое можно истолковать как «по умолчанию», целесообразно реализовать этот трейт.


Если вас не устраивают возможности [std] по вычислению значений для [`Default`], рассмотрите возможность использования крейта [smart-default]. Пример довольно нагляден:

```rust
#[derive(SmartDefault)]
enum Foo {
    Bar,
    #[default]
    Baz {
        #[default = 12]
        a: i32,
        b: i32,
        #[default(Some(Default::default()))]
        c: Option<i32>,
        #[default(_code = "vec![1, 2, 3]")]
        d: Vec<u32>,
        #[default = "four"]
        e: String,
    },
    Qux(i32),
}
```

<h2>Синтаксис только для struct !!!</h2>

Замечательно то, что при использовании реализации [`Default`] вы можете создать экземпляр вашей структуры, используя только значения, отличные от значений по умолчанию, а все остальные поля заполнить значениями по умолчанию:

```rust
let x = Foo { bar: baz, ..Default::default() };
```




## Cloning and copying

По умолчанию все типы в [Rust] следуют ['move semantics'][1].

Если вам нужна копия значения, то его тип должен реализовывать трейт [`Clone`] (см. [official docs][`Clone`]), а копия создается путем __явного__ вызова методов [`Clone`]. Клонирование может быть __как дешевой, так и дорогой__ операцией в зависимости от семантики типов.

Однако, маркерный трейт [`Copy`] (см. [official docs][`Copy`]) включает «семантику копирования» для типа, поэтому значение __копируется неявно__ каждый раз, когда оно передается. Вот почему копирование всегда должно выполнять __простую побитовую операцию копирования__.

[Official `Copy` docs][`Copy`] достаточно подробно объясняет, какие типы _должны_ быть [`Copy`], а какие типы _не могут_ быть:


> Некоторые типы данных нельзя безопасно скопировать. Например, копирование `&mut T` создаст псевдонимную изменяемую ссылку. Копирование `String` приведет к дублированию ответственности за управление буфером `String`, что вызовет двойное освобождение памяти.
> 
> Generalizing the latter case, any type implementing `Drop` can't be `Copy`, because it's managing some resource besides its own `size_of::<T>` bytes.
> 


> Generally speaking, if your type can implement `Copy`, it should. Keep in mind, though, that implementing `Copy` is part of the public API of your type. If the type might become non-`Copy` in the future, it could be prudent to omit the `Copy` implementation now, to avoid a breaking API change.

To better understand the topic, read through:
- [Official `Clone` docs][`Clone`]
- [Official `Copy` docs][`Copy`]
- [HashRust: Moves, copies and clones in Rust][2]

<h3>Какова функция трейта Default в Rust?</h3>

В Rust трейт Default предоставляет стандартизированный способ инициализации типа с «разумным» или «нулевым» начальным состоянием. Хотя многие типы имеют собственный конструктор new(), трейт Default позволяет использовать абстракцию в обобщенном программировании, где конкретный метод инициализации может быть неизвестен.

Основные цели:

1. Стандартизированная инициализация: Она предлагает единый интерфейс (Default::default()) для получения начального экземпляра типа без необходимости вручную указывать все поля.
2. Обобщенное программирование: Это необходимо для обобщенных функций или контейнеров, которым необходимо создавать новые экземпляры типа T, не зная его конкретного конструктора (например, Option::unwrap_or_default()).
3. Частичная инициализация: Она включает синтаксис обновления функциональной записи, где вы можете указать только те поля, которые хотите изменить, а остальные заполнить из экземпляра по умолчанию.

```rust
let options = SomeOptions { foo: 42, ..Default::default() };
```

Типичные сценарии использования:

- Структуры конфигурации: Полезно для больших структур, где пользователи могут захотеть изменить только один или два параметра.
- Инициализация коллекции: Предоставление пустой начальной точки для таких типов, как Vec, HashMap или String.
- Значения по умолчанию в стандартной библиотеке:
    - Числа: По умолчанию 0.
    - Логические значения: По умолчанию false.
    - Опция: По умолчанию None.

Default против new()

Хотя оба метода могут использоваться для инициализации, они следуют разным соглашениям:

- new(): Общее соглашение об именовании основного конструктора типа; он может принимать несколько аргументов и иметь любое имя.
- default(): Метод трейта, который не может принимать аргументы и необходим для использования типа в обобщенных контекстах, где конкретные конструкторы неизвестны.

<h3>На что способна директива #[derive(Default)] из стандартной библиотеки? В чём её ошибка? Какие есть альтернативы?</h3>

На что способен #[derive(Default)]:

Стандартный макрос derive, предоставляемый std, автоматизирует реализацию трейта Default для структур и перечислений.

- Рекурсивная инициализация: Он устанавливает каждое поле структуры в значение Default::default() этого поля (например, 0 для целых чисел, "" для строк).
- Поддержка перечислений: Начиная с Rust 1.62, его можно использовать для перечислений, если вы пометите один из вариантов атрибутом #[default].
- Нулевая стоимость: Это преобразование на этапе компиляции; оно генерирует тот же самый код, который вы бы написали вручную.

Что в нём «не так» (ограничения):

Несмотря на стандартность, ему не хватает гибкости в трёх основных областях:
1. Отсутствие пользовательских значений

Вы не можете указать значение по умолчанию, отличное от состояния «ноль» типа.
    - Проблема: Если вы хотите, чтобы поле u32 по умолчанию имело значение 100 вместо 0, или чтобы строка по умолчанию имела значение «localhost», #[derive(Default)] вам не поможет. Вам придётся реализовать трейт вручную.

2. Ненужные обобщенные ограничения

Стандартный метод `derive` добавляет ограничение по умолчанию ко всем параметрам обобщенных типов, даже если они строго не требуются для реализации по умолчанию (например, если обобщенный тип обернут в `PhantomData` или указатель).

Проблема: это может привести к ошибкам «неудовлетворенное ограничение трейта» в сложных обобщенных структурах, где сам параметр обобщенного типа не реализует `Default`, но структура логически могла бы это сделать.

3. Сложности с `Enums`

Хотя библиотека поддерживает перечисления, это возможно только в том случае, если вариант по умолчанию является вариантом юнита (без полей) или если вас устраивает, что поля этого варианта также являются собственными значениями по умолчанию. Вы не можете определить вариант по умолчанию, требующий пользовательских данных.

<hr>

Альтернативы:

1. smart-default (The Logic Specialist)

Крейт smart-default — самая популярная альтернатива для проектов, требующих пользовательских значений. Он позволяет задавать значения по умолчанию непосредственно в атрибутах.

```rust
#[derive(SmartDefault)]
struct Config {
    #[default = 8080]
    port: u16,
    #[default = "https://api.example.com"]
    endpoint: String,
}
```

2. derivative (The Flexibility Specialist)

Крейт derivative позволяет более точно контролировать процесс вычисления значений по умолчанию (и других характеристик), в частности, решая проблему «ненужных общих ограничений».

```rust
#[derive(Derivative)]
#[derivative(Default)]
struct MyBox<T> {
    #[derivative(Default(value="Box::new(None)"))]
    content: Box<Option<T>>, // Works even if T is not Default
}
```

3. Ручная реализация

Когда логика зависит от переменных среды выполнения или сложных вычислений, ручная реализация по умолчанию остается наиболее прозрачным и эффективным методом.

4. educe

Современная альтернатива, похожая на derivative, но с более современной реализацией процедурных макросов, часто используемая в критически важных с точки зрения производительности или очень универсальных библиотеках.

<h3>Что означает слово `Clone` в семантическом смысле?</h3>

В Rust трейт Clone представляет собой явное, глубокое дублирование объекта.

В то время как компилятор автоматически обрабатывает «перемещения» и «копирования», Clone — это преднамеренное действие, предпринимаемое программистом для создания второго, независимого экземпляра данных.

1. Семантическое значение: Независимая жизнеспособность

Семантически, клонирование означает, что после операции у вас есть два отдельных объекта, каждый из которых «владеет» своими ресурсами. Изменения, внесенные в клон, не влияют на оригинал, и оригинал может быть уничтожен без влияния на клон.
Это противопоставляется копированию, которое представляет собой неявное побитовое дублирование небольших данных, хранящихся только в стеке.

2. Стоимость дублирования. 

В отличие от большинства операций в Rust, которые имеют «нулевую стоимость», клонирование — это сигнал производительности. 
- Оно часто включает выделение памяти в куче. 
- Обычно оно имеет временную сложность O(n) (где n — объем копируемых данных). 
- Поскольку оно может быть дорогостоящим, Rust требует явного вызова этой операции через `.clone()`, чтобы снижение производительности было видно в исходном коде.

3. Глубокое и поверхностное дублирование

Большинство реализаций Clone (включая те, которые генерируются с помощью #[derive(Clone)]) выполняют глубокое копирование:

- Vec<T>: При клонировании вектора Rust выделяет новую память в куче и клонирует каждый элемент в это новое пространство.
- String: Клонирование строки копирует весь текст в новое место в куче.

Исключение (поверхностное клонирование):

Умные указатели, такие как `Rc<T>` и `Arc<T>`, переопределяют семантику клонирования. При клонировании `Arc` не копируются исходные данные. Вместо этого увеличивается счетчик ссылок, и вы получаете новый указатель на те же данные. Это «дешевое» клонирование.

4. Связь с признаком Copy

Семантически, Copy является подтипом Clone.

- Если тип является Copy (например, i32), он также должен быть Clone.
- Для типов Copy метод .clone() делает то же самое, что и побитовое копирование.
- Однако многие типы являются Clone, но не могут быть Copy (например, String), поскольку они владеют ресурсами, которые нельзя безопасно дублировать простым копированием битов (что привело бы к ошибкам двойного освобождения памяти).

5. Сводная таблица

| Feature |	Clone |	Copy |
| ------- | ----- | ---- |
| Invocation | Explicit (.clone()) | Implicit (Assignment/Passing) |
| Memory | Usually Heap (Deep) | Always Stack (Bitwise) |
| Complexity | O(n) (Usually) | O(1) (Always) |
| Ownership	| Creates a new owner |	Duplicates the value |

Вкратце: используйте клонирование, когда вам нужна новая, независимая версия ресурса, и вы готовы понести потери в производительности, связанные с её созданием.

<h3>Что означает Copy в семантическом смысле? Как оно связано со словом Clone? Какие у него ограничения и почему?</h3>

В Rust Copy — это маркерный трейт, изменяющий фундаментальное поведение переменной во время присваивания или при передаче её в функцию.

1. Семантическое значение: Неявное побитовое дублирование
Семантически Copy означает, что тип настолько прост, что его дублирование так же легко, как копирование его битов в память (memcpy).

- Перемещение против копирования: Обычно в Rust используется «семантика перемещения» — если вы присвоите let b = a, a станет недействительным. Если тип является копируемым, Rust использует «семантику копирования» — a остается совершенно действительным, потому что для b был создан побитовый дубликат.
- Неявное копирование: В отличие от клонирования, которое необходимо вызывать явно, копирование происходит автоматически и незаметно, в фоновом режиме.

2. Как это связано с Clone

В иерархии трейтов Rust Copy является уточнением Clone.

- Связь супертрейта: трейт Copy: Clone {}. Это означает, что любой тип, обладающий свойством Copy, должен также реализовывать свойство Clone.
- Функциональная идентичность: для типа Copy реализация метода .clone() должна делать то же самое, что и побитовое копирование.
- Намерение: Clone — это общая возможность дублирования (потенциально дорогостоящая), в то время как Copy — это гарантия того, что дублирование тривиально и может быть выполнено неявно компилятором.

3. Ограничения трейта Copy

Ограничения трейта Copy являются строгими и вводятся для поддержания основных гарантий безопасности памяти в Rust.

А. Отсутствие права собственности на ресурсы (проблема двойного освобождения памяти)

Тип не может быть скопирован, если он владеет ресурсом, требующим очистки (например, памятью кучи, дескриптором файла или сетевым сокетом).

B. Ограничение компонента

Struct или Enum может реализовывать интерфейс Copy только в том случае, если все её члены также реализуют интерфейс Copy.

- Если у вас есть структура с десятью полями типа i32 и одним полем типа String, вся структура не может быть реализована как Copy.

C. Ограничения на изменяемость

Вы не можете реализовать метод Copy для типов, использующих "внутреннюю изменяемость" (например, RefCell или Mutex), или для изменяемых ссылок (&mut T).

Почему: Копирование изменяемой ссылки создаст два уникальных пути для одновременного изменения одних и тех же данных, что нарушит фундаментальные правила заимствования Rust и приведет к состояниям гонки данных.

D. Ожидания относительно производительности

Хотя это и не является технической ошибкой компилятора, это ограничение проектирования: как правило, не следует реализовывать функцию Copy для очень больших структур (например, массива из 10 000 целых чисел).

Почему: Поскольку функция Copy является неявной, разработчик может случайно вызвать массовое копирование памяти, просто передав переменную в функцию, что приведет к неожиданному снижению производительности.
