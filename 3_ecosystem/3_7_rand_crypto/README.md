## Случайность

Для генерации случайных значений в экосистеме [Rust] существует крейт [`rand`], предоставляющий __унифицированный интерфейс__ и множество __реализаций генератора случайных значений__ с различными гарантиями качества и производительности__.


[The Rust Rand Book] не только объясняет, как использовать примитивы крейта [`rand`], но и является хорошим введением в [основы проблемы генерации случайных значений][1] и [как она решается в современном мире][2]. Прочитайте её, чтобы понять, какие примитивы следует использовать в разных ситуациях:
- когда целью является результативность;
- когда целью является криптографическая безопасность и высокое качество статистических данных;
- Что подходит для общего пользования.

Один из наиболее распространенных случаев, когда необходимо генерировать случайные значения, — это генерация универсальных уникальных идентификаторов (таких как [UUID]). К счастью, в [Rust] уже есть крейт [`uuid`], который реализует [все версии спецификации UUID][3].

## Шифрование и подписание

Хотя на данный момент в [Rust] нет криптографической библиотеки, в его экосистеме есть множество хорошо реализованных (и все еще развивающихся) библиотек для различных целей.


### [`ring`]

Библиотека [`ring`] реализует основной набор криптографических операций, предоставляемых через простой в использовании (и трудно для неправильно используемый) API. Она начиналась как подмножество известной библиотеки [BoringSSL] (строка «ring» является подстрокой «Bo_ring_SSL»), поэтому наследует часть её кода и регулярно объединяет изменения из неё.


[`ring`] ориентирован на криптографию общего назначения. Если вам нужны только базовые криптографические примитивы — это то, что вам нужно. Используйте его, когда вам необходимо создать:
- цифровая подпись;
- просто зашифровать незашифрованные данные;
- вывод ключа;
- и так далее...

Если вам требуются более сложные реализации (например, проверка сертификатов WebPKI [X.509] или криптографические протоколы, такие как [TLS], [SSH]), рассмотрите возможность использования других библиотек (которые часто построены на основе [`ring`]).


### [dalek]

В то время как [`ring`] ориентирован на предоставление универсальных криптографических примитивов, крейты [dalek] предоставляют лишь несколько, но ориентированы на реализацию лучших теоретических примитивов.

Если вы собираетесь создавать что-то, использующее только высокоуровневые криптографические примитивы (например, [Curve25519] для подписи и проверки), вам стоит попробовать [dalek].


### [AWS] Libcrypto

[`aws-lc-rs`] — это криптографическая библиотека, совместимая с [`ring`], использующая криптографические операции, предоставляемые [AWS-LC].


Мотивация [предоставленная авторами][18] вполне понятна сама по себе:
> Разработчикам на [Rust] все чаще требуется развертывать приложения, соответствующие криптографическим требованиям правительств США и Канады. Мы оценили, как обеспечить криптографию, соответствующую стандарту [FIPS], на идиоматичном и производительном языке [Rust], построенном на основе нашего решения AWS-LC. Мы обнаружили, что популярная библиотека [`ring`] удовлетворяет большую часть криптографических потребностей сообщества [Rust], но не отвечает потребностям разработчиков, предъявляющих требования [FIPS]. Наша цель — предложить замену `ring`, которая обеспечит поддержку [FIPS] и будет совместима с API `ring`. Разработчики на [Rust] с заданными криптографическими требованиями смогут беспрепятственно интегрировать `aws-lc-rs` в свои приложения и развертывать их в регионах [AWS].

Дополнительная информация:
- [Sean McGrai: Introducing AWS Libcrypto for Rust, an Open Source Cryptographic Library for Rust][19]

## TLS / SSL

Для использования [TLS] в экосистеме [Rust] в настоящее время существуют два распространенных решения:

### [`native-tls`]

Крейт [`native-tls`] представляет собой абстракцию над платформенно-специфичными реализациями [TLS]. Он использует [SChannel] в Windows (через крейт [`schannel`]), Secure Transport в OSX (через крейт [`security-framework`]), [OpenSSL] на всех остальных платформах (через крейт [`openssl`]) и предоставляет унифицированный интерфейс для использования этих библиотек.

Хотя это решение требует наличия внешних библиотек, не относящихся к Rust, оно является стабильным и основано на готовых к использованию реализациях TLS.

### [`rustls`]

Крейт [`rustls`] — это реализация [TLS] на чистом [Rust]. Он построен на основе крейтов [`ring`] и [`webpki`].


Несмотря на то, что это довольно многофункциональное решение, оно [не имеет хорошей поддержки старой и устаревшей криптографии][14] и пока не имеет стабильной версии. Рассмотрите возможность его использования, если устаревшие технологии для вас не имеют значения.

### В чём заключается главный компромисс при генерации случайных чисел? Как это применяется на практике?

В Rust главный компромисс при генерации случайных чисел (RNG) заключается в выборе между криптографической стойкостью и скоростью выполнения. Этот баланс выражается формулой: __Безопасность__ <-> __Предсказуемость__ <-> __Производительность__. 

1. #### Суть компромисса

Криптографическая стойкость (CSPRNG)

- Пример: StdRng или прямые вызовы ОС (getrandom).
- Плюс: Числа невозможно предсказать. Даже если злоумышленник узнает миллион предыдущих чисел, он не вычислит следующее.
- Минус: Это медленно. Требует обращения к энтропии операционной системы (системные вызовы) или сложных математических преобразований (ChaCha20).

Скорость (Non-Crypto PRNG)

- Пример: SmallRng, Pcg64, Xoshiro2048.
- Плюс: Экстремально быстро (в десятки раз быстрее CSPRNG). Работает полностью в пользовательском пространстве, используя простые битовые сдвиги и умножения.
- Минус: Предсказуемость. Зная небольшую последовательность чисел, можно восстановить внутреннее состояние генератора («зерно» / seed) и предсказать все будущие значения.

2. #### Как это применяется на практике?

В экосистеме Rust (через крейт [rand](https://docs.rs/rand/latest/rand/)) выбор автоматизирован под конкретные сценарии:

А. По умолчанию: Безопасность прежде всего

Метод `thread_rng()` возвращает генератор, который является:

- Криптографически стойким (сейчас это обычно ChaCha12).
- Периодически обновляемым (автоматически подмешивает новую энтропию из ОС).
    - Применение: Генерация паролей, токенов сессий, ключей шифрования.

Б. Игры и симуляции: Скорость

Если вам нужно генерировать миллионы частиц в секунду или шум Перлина, `thread_rng()` будет «бутылочным горлышком».

- Решение: Используйте SmallRng.
- Применение: Процедурная генерация миров, частицы, Монте-Карло симуляции.

В. Тестирование: Воспроизводимость

Иногда вам нужно, чтобы «случайность» была одинаковой при каждом запуске (например, для отладки бага).

- Решение: Использование фиксированного зерна (SeedableRng).
- Применение: Регрессионные тесты, Property-based testing (как мы обсуждали в proptest).

3. #### Сводная таблица выбора

|Тип генератора|Крейт/Метод|Стойкость|Скорость|Использование|
|--------------|-----------|---------|--------|-------------|
|ThreadRng|rand::thread_rng|Да|Средняя|Общие задачи, Web, Security|
|SmallRng|rand::rngs::SmallRng|Нет|Очень высокая|Игры, математика|
|StdRng|rand::rngs::StdRng|Да|Высокая|Предсказуемо лучший CSPRNG для платформы|

#### Практический совет:

Никогда не используйте SmallRng для чего-то, что связано с безопасностью (даже для создания ID заказов, если они должны быть секретными). В Rust  популярна атака «предсказания состояния», когда по публичным ID восстанавливают генератор и крадут данные.

### Что такое симметричная криптография? Что такое асимметричная криптография? Какие преимущества имеет каждая из них?

1. #### Симметричная криптография (Symmetric Cryptography)

В _симметричном шифровании_ для зашифровки и расшифровки данных используется один и тот же секретный ключ. Это похоже на обычный сейф: кто положил в него вещь, закрыл его ключом, тот же (или тот, у кого есть копия) должен этим же ключом его открыть.

- Распространенные алгоритмы в Rust: AES-GCM, ChaCha20-Poly1305.
- Библиотеки: aes-gcm, chacha20poly1305.

Преимущества:

- Экстремальная скорость: Работает в тысячи раз быстрее асимметричной. - Процессоры (Intel/AMD) имеют аппаратное ускорение для AES.
- Эффективность: Зашифрованные данные почти не увеличиваются в размере.
- Простота: Идеально подходит для шифрования больших объемов данных (файлы, базы данных, потоковое видео).


2. #### Асимметричная криптография (Asymmetric Cryptography)

Здесь используются два ключа: публичный (__Public key__) для зашифровки и приватный (__Private key__) для расшифровки. Публичный ключ можно раздавать всем, а приватный должен храниться в строжайшем секрете.

- Распространенные алгоритмы в Rust: Ed25519 (подписи), X25519 (обмен ключами), RSA (устаревает), Kyber (постквантовый стандарт 2026 года).
- Библиотеки: ed25519-dalek, ring.

Преимущества:

- Решение проблемы передачи ключа: Вам не нужно передавать секретный пароль собеседнику. Вы просто даете ему публичный ключ.
- Цифровые подписи: Позволяет доказать, что сообщение пришло именно от вас и не было изменено (целостность и авторство).
- Масштабируемость: Удобно для систем с миллионами пользователей (как HTTPS/TLS).

3. #### Сравнение и гибридный подход

В реальном мире (например, в протоколе TLS/HTTPS или SSH) Rust-приложения используют гибридную схему:

- Асимметричная криптография используется в начале сессии, чтобы безопасно договориться об общем секретном ключе (алгоритм Диффи-Хеллмана).
- Симметричная криптография используется далее для шифрования всего основного трафика, так как она намного быстрее.

|Характеристика|Симметричная|Асимметричная|
|--------------|------------|-------------|
|Количество ключей|1 (общий)|2 (публичный + приватный)|
|Скорость|Очень высокая|Низкая|
|Объем данных|Любой (ГБ, ТБ)|Маленький (ключи, хэши)|
|Основной риск|Кража единственного ключа|Утеря приватного ключа|

### Что такое подпись в асимметричной криптографии? Что такое шифрование в асимметричной криптографии? Как они работают при наличии одних и тех же закрытого и открытого ключей?

В асимметричной криптографии на Rust (используя современные библиотеки вроде [ring](https://docs.rs/ring/latest/ring/) или [ed25519-dalek](https://docs.rs/ed25519-dalek/latest/ed25519_dalek/)) подпись и шифрование — это две зеркальные операции.
Главное отличие: кто использует какой ключ.

1. #### Шифрование (Encryption)

Цель: Конфиденциальность (только получатель может прочитать).

- Как это работает: Отправитель берет открытый ключ (__Public Key__) получателя и «запирает» им данные.
- Результат: Математически данные превращаются в шум, который может расшифровать только владелец закрытого ключа (__Private Key__).
- В Rust: Для этого часто используется алгоритм ECIES или гибридное шифрование через [crypto_box](https://docs.rs/crypto_box/latest/crypto_box/).

2. #### Подпись (Digital Signature)

Цель: Авторство и целостность (доказать, что это прислал именно ты и данные не меняли).

- Как это работает: Вы берете хеш своих данных и «заверяете» его своим закрытым ключом (__Private Key__).
- Результат: Создается небольшая метка (подпись). Любой человек, имея ваш открытый ключ (__Public Key__), может проверить, что подпись совпадает с данными.
- В Rust: Стандартом является алгоритм Ed25519, реализованный в крейте ed25519-dalek.

3. #### Как они работают вместе (на одной паре ключей)

Если у вас есть пара ключей (например, на базе кривой Curve25519), вы можете выполнять обе операции, но логика движения информации будет разной:

|Операция|Кто использует Закрытый ключ?|Кто использует Открытый ключ?|	Что доказываем?|
|--------|-----------------------------|-----------------------------|---------------|
|Шифрование|Получатель (чтобы прочитать)|Отправитель (чтобы скрыть)|	Никто, кроме владельца, не увидит.|
|Подпись|Отправитель (чтобы заявить)|Получатель (чтобы проверить)|Это точно прислал владелец.|

#### Практический пример на Rust

Представьте, что Алиса хочет отправить Бобу секретное и подписанное письмо:

- Подпись: Алиса подписывает текст своим закрытым ключом. Теперь Боб знает, что это написала она.
- Шифрование: Алиса шифрует текст и подпись открытым ключом Боба. Теперь только Боб может это открыть.
- Получение: Боб расшифровывает всё своим закрытым ключом и проверяет подпись открытым ключом Алисы.

### Что такое хеш-функция? Что такое хеширование паролей? Почему для хеширования паролей недостаточно использовать только обычную хеш-функцию?

В Rust различие между обычным хешированием и хешированием паролей — это критическая граница между производительностью и безопасностью.

1. #### Что такое хеш-функция в Rust?

__Хеш-функция__ — это алгоритм, который преобразует входные данные любого размера в строку фиксированной длины (хеш).

- Свойство: Один и тот же вход всегда дает один и тот же выход. Даже изменение одного бита полностью меняет хеш.
- В Rust: Стандартный трейт [std::hash::Hash](https://doc.rust-lang.org/std/hash/trait.Hash.html) используется для быстрой работы коллекций вроде HashMap. По умолчанию Rust использует алгоритм SipHash, который быстр и защищен от атак типа «отказ в обслуживании» (DoS).

2. #### Что такое хеширование паролей?

Это процесс превращения пароля пользователя в «отпечаток», который хранится в базе данных. Мы никогда не храним пароли в открытом виде. При входе пользователя мы хешируем введенный им пароль и сравниваем результат с тем, что лежит в БД.

3. #### Почему обычной хеш-функции (SHA-256, MD5, SipHash) НЕДОСТАТОЧНО?

Обычные функции (даже криптографические, такие как SHA-256) создавались для максимальной скорости. В этом и заключается их главная проблема для паролей:

- Скорость перебора (Brute Force): Современная видеокарта может вычислять миллиарды хешей SHA-256 в секунду. Злоумышленник может подобрать простой пароль за доли секунды.
- Радужные таблицы (Rainbow Tables): Если два пользователя имеют одинаковый пароль «12345», их хеши SHA-256 будут идентичны. Злоумышленник может заранее составить таблицу хешей для всех популярных паролей.
- Отсутствие «соли» (Salt): Обычные функции не заставляют вас использовать уникальную случайную добавку к каждому паролю, что делает базу данных уязвимой для массового взлома.

4. #### Как это работает правильно в 2026 году?

Для паролей используются функции формирования ключа (__KDF__), такие как __Argon2id__ (золотой стандарт), __bcrypt__ или __scrypt__. Они решают проблемы следующим образом:

- Искусственное замедление: Эти алгоритмы специально сделаны медленными. Вы можете настроить их так, чтобы проверка одного пароля занимала 500 мс. Для пользователя это незаметно, а для хакера — катастрофа (скорость перебора падает в миллионы раз).
- Потребление памяти (Memory Hardness): Argon2 требует много оперативной памяти. Это делает невозможным использование дешевых ASIC-чипов или видеокарт для массового взлома.
- Обязательная соль (Salt): Алгоритм сам генерирует уникальную случайную строку для каждого пароля. Даже если у двух юзеров пароль одинаковый, их хеши в БД будут абсолютно разными.

#### Практика на Rust

Для работы с паролями используйте крейт [argon2](https://docs.rs/argon2/latest/argon2/) (часть проекта RustCrypto).

```rust
use argon2::{
    password_hash::{
        rand_core::OsRng,
        PasswordHash, PasswordHasher, PasswordVerifier, SaltString
    },
    Argon2
};

// 1. Хеширование
let password = b"my_super_secret_password";
let salt = SaltString::generate(&mut OsRng);
let argon2 = Argon2::default();
let password_hash = argon2.hash_password(password, &salt).unwrap().to_string();

// 2. Проверка
let parsed_hash = PasswordHash::new(&password_hash).unwrap();
assert!(argon2.verify_password(password, &parsed_hash).is_ok());
```

__Итог__: Используйте std::hash для данных (быстрый доступ), но всегда используйте Argon2id для паролей (медленная защита).

### Что такое сравнение за постоянное время? Когда и почему его следует использовать?

В Rust сравнение за постоянное время (Constant-Time Comparison) — это метод сравнения двух массивов данных (обычно хешей или токенов), при котором время выполнения операции не зависит от того, насколько похожи эти данные или в каком месте обнаружено первое различие.

В обычной жизни мы используем «короткое замыкание» (short-circuiting): как только мы видим, что первые буквы слов разные, мы сразу говорим «не равны». В криптографии это __смертельно опасно__.


1. #### Почему обычное сравнение (==) опасно?

Стандартная реализация PartialEq для строк или векторов в Rust работает максимально быстро:

```rust
// Упрощенная логика обычного ==
for i in 0..len {
    if a[i] != b[i] { return false; } // Выход сразу при несовпадении!
}
return true;
```

Проблема: Злоумышленник может замерять время ответа вашего сервера с точностью до наносекунд (Timing Attack).

- Если правильный токен secret, а злоумышленник прислал sXXXXX, ответ придет чуть позже (проверено 1 совпадение).
- Если он прислал aXXXXX, ответ придет чуть раньше (0 совпадений).
- Перебирая символы и замеряя микро-задержки, хакер может «угадать» секретный ключ посимвольно за очень короткое время.
