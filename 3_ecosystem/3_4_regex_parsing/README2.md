## Использование регулярных выражений и парсера Winnow для разбора строк на RUST.

## Задание

Грамматика из `std::fmt` (упрощённо):

```text
format_spec := [[fill]align][sign]['#']['0'][width]['.' precision]type
```

Нужны две реализации: **regex** и **свой парсер**. В проекте regex — в `src/main.rs`, комбинаторный парсер — в `src/lib.rs` на **winnow** (в README ещё фигурируют nom, pest и т.д.; фактически выбран winnow). Старый вариант парсера лежит в `src/lib.rs.old`.

Результат в обоих случаях один:

```rust
(Option<Sign>, Option<usize>, Option<Precision>)
```

- `Sign`: `Plus` / `Minus`
- `Precision`: `Integer(n)` (`.8`), `Argument(n)` (`.1$`), `Asterisk` (`.*`)

Остальное (`fill`/`align`, `#`, `0`, `type`) нужно **съесть**, чтобы не сбить позиции, но в кортеж не класть.

## Regex (`src/main.rs`)

`parse` компилирует выражение **один раз** через `OnceLock<Regex>` — то, что курс отдельно подчёркивает: `Regex::new` дорогой.

Флаг `(?x)` — пробелы и комментарии в шаблоне игнорируются. Логика по частям:

| Фрагмент | Что делает |
|---|---|
| `(?:[^<>\^]?[<>\^])?` | необязательные fill + align (`>`, `a^`, …) |
| `(?P<sign>[\+-])?` | именованная группа знака |
| `\#?` `0?` | флаги, без захвата |
| `(?P<width>\d+)?` | ширина |
| `\.(?P<precision>(\*\|(?P<raw_width>\d+)(?P<end_width>\$)?))?` | точность: `*`, число, или число + `$` |
| `(?:(\?\|x\?\|X\?\|_\|r\#))?` | type (`?`, `x?`, `_`, `r#`) |

Дальше `captures`: `sign` → enum, `width` → `usize`, `precision` → `Asterisk` / `Argument` / `Integer` по наличию `end_width` (`$`).

`main` гоняет `parse` на строках вроде `"-8_"` и ниже — **черновик туториала winnow** (главы 1–4: `any`, `literal`, `one_of`, `take_while`, `preceded`, списки через `opt`+`terminated`). К заданию `format_spec` это не относится.

## Winnow (`src/lib.rs`)

`parse_format_spec` читает `&mut &str` слева направо (каждый успешный парсер **съедает** токены). Обёртка `parse` копирует строку в `String` и вызывает `.parse_next`.

Порядок шагов совпадает с грамматикой:

1. **fill/align** — `peek(preceded(any, one_of(['<','>','^'])))`: если второй символ — выравнивание, первый — fill; оба потребляются. Иначе опционально один символ align.
2. **sign** — `opt(one_of(['+','-']))` → `Sign`.
3. **`#` и `0`** — `opt`, результат отбрасывается.
4. **width** — `opt(digit1)` + `parse::<usize>()`.
5. **precision** — `opt(preceded(".", alt( ("*", …), (digit1, opt("$")) )))`.
6. **type** — `opt(alt(("?", Caseless("x?"), "_", "r#")))`.

`Caseless("x?")` покрывает и `x?`, и `X?`.

Тип ошибки: `PResult` = `Result<_, ErrMode<ContextError>>`. На невалидных числах — `panic!`, не `syn`-подобные ошибки.

## Тесты

Одинаковые фикстуры в `main.rs` (`mod spec`) и `lib.rs` (`mod tests`):

| Вход | sign | width | precision |
|---|---|---|---|
| `""` | none | none | none |
| `">8.*"` | none | 8 | `Asterisk` |
| `">+8.*"` | `Plus` | 8 | `Asterisk` |
| `"-.1$x"` | `Minus` | none | `Argument(1)` |
| `"a^#043.8?"` | none | 43 | `Integer(8)` |

Последний пример проверяет всю цепочку: fill `a`, align `^`, `#`, zero-pad `0`, width `43`, `.8`, type `?`.

Запуск: `cargo test` — тесты бинарника и библиотеки.

## Что проект показывает

- Regex в Rust — **конечный автомат**, линейный поиск, без backreferences; компиляция один раз (`OnceLock`).
- Для структурированной грамматики комбинаторы удобнее: шаги читаются как грамматика, lookahead (`peek`) отличает `fill+align` от одного `align`.
- Практический компромисс: regex короче, но хрупче; winnow длиннее, зато порядок правил явный.

`main.rs` раздут учебными вставками winnow; рабочий regex-парсер — функция `parse` и модуль `spec`. Библиотека — «чистый» парсер задания без туториала.
